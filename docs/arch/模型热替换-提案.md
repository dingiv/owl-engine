# 模型热替换（Model Hot Swap）提案

> 状态：**提案，未施工**（2026-10-21）
>
> 目标读者：owl 引擎 / server / store 维护者。
>
> 本文只定义问题、边界、候选架构、状态契约与施工阶段；**不涉及具体代码落地**。
> 任何“推荐”都不是最终裁决，施工前需按 §15 的待拍板项逐条确认。

---

## 0. 一句话结论

一个固定端口的 owl server，启动时登记多个完整 profile；同一时刻**只有一个模型驻留显存**。
客户端通过**显式管理端点**切换模型：先排空在飞 turn，把当前模型的**post-repack 设备权重**
dump 到磁盘，退出旧 worker；再启动目标 worker，从权重快照恢复并重建池/图/会话。
KV / GDN 快照 / 前缀链等模型私有状态，作为第二阶段通过 store 磁盘层做**按模型隔离的休眠**；
CUDA 图、allocator、设备指针等进程内状态**不参与快照**。

## 1. 需求

### 1.1 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| HS-01 | 启动时登记 N 个模型 profile，给出默认模型 | P0 |
| HS-02 | 显式管理端点切换当前模型；同一时刻只允许一个切换 | P0 |
| HS-03 | 切换前排空在飞请求；超时后精确中止剩余 turn | P0 |
| HS-04 | 卸载当前模型时把**最终设备权重** dump 到磁盘 | P0 |
| HS-05 | 再次切回时从权重快照恢复，**不重新做 Marlin/AWQ/GGUF repack** | P0 |
| HS-06 | 目标模型加载失败时可回退到上一个模型 | P1 |
| HS-07 | `/v1/models` 展示配置模型、当前 active、加载状态、最近切换结果 | P0 |
| HS-08 | 切换期间新请求得到明确的 `503 model_switching`，不静默挂起 | P0 |
| HS-09 | 可选：KV 链 / GDN 快照 / 会话元数据按模型休眠并在切回时恢复 | P1 |
| HS-10 | 缓存损坏、磁盘满、worker 崩溃均有明确降级路径 | P1 |

### 1.2 非目标（本提案明确不做）

- **不做多模型同时驻留**：2×3080 20G 装不下两个 27B；切换期间没有“旧模型继续服务”的蓝绿窗口。
- **不做跨模型 KV 共享**：tokenizer / 层几何 / KV dtype 不同，KV 不可复用。
- **不做全 VRAM 镜像恢复**：CUDA graph 节点、设备指针、allocator 元数据、kernel handle 都不可直接重定位。
- **不做任意代码/引擎版本热升级**：worker 二进制与缓存格式必须匹配；引擎版本变化 = 缓存失效。
- **不做请求级排队迁移**：切换时在飞/排队的 turn 按 §7 处理，不迁移到新模型。
- **不做自动按请求 `model` 字段切换**：按用户裁决，v1 **只允许显式管理端点**。
- **不承诺亚秒切换**：权重恢复 + worker 启动 + 池/图重建是秒级到十秒级操作。

## 2. 当前架构事实（施工前必须承认的约束）

### 2.1 单模型、一次性装配

当前入口：

```text
apps/server/src/main.rs::main()
  -> ServerConfig::load_resolved()
  -> 选卡 / GPU 卡锁
  -> spawn "owl-engine" 线程
       -> actor_main()
            -> engine_of()                  // Engine::new，绑定 GPU
            -> load_shard()                 // 权重 + tokenizer + rope + 视觉塔
            -> Engine::run(model)            // 池 / 图 / 会话 / warmup
            -> actor::run_actor(&mut running)
  -> bind 公共端口
  -> accept loop
```

关键事实：

- `ServerConfig` 只有一个 `[model]`；`profiles/*.toml` 是完整单模型档。
- `RunningEngine` **非 Send**，只在 `owl-engine` 线程内独占；HTTP 层只持 `mpsc` 提交通道。
- 引擎装配是“构造 → 装载 → `run()` → 泵”的一次性生命周期；没有通用的
  “卸载当前引擎 → 再装配另一个引擎”入口。
- `GpuClient::spawn_with` 会起独立 GPU server 线程；`GpuCtx` / `GpuServer`
  的收尾路径存在，但当前主要由进程退出承担，不是热切换路径。
- TP2 档还有 `TpEngine::shutdown_tp` / `retire_rank` 的显式收尾面；模型切换必须复用这些
  收尾语义，不能直接 `drop` 了事。

### 2.2 装载与 repack

- `crates/models/src/formats/load.rs` 的 `eval_load` / `load_group` 负责把
  `Loadable::layout()` 的 `Want` 物化到设备。
- 三个臂：
  - `load_direct`：safetensors / GGUF 源 → 目标 dtype → `wt.<key>`；
  - `load_device_rearrange`：源 packed → GPU `ct_repack` → `repack.<key>`（Marlin B）；
  - `load_transposed`：tied 头等转置 → `wt.<key>`。
- `LoadManifest` 已经记录 `(key, dtype, shape, layout, block, csum)`，这是权重快照的
  天然清单来源。
- 当前**没有**权重装载缓存；每次启动都重新读源、重新 repack、重新 H2D。

### 2.3 已有可复用的状态持久化

- `crates/store` 已有磁盘层：
  - KV 链内容 + `ChainIndex`；
  - GDN 快照 `SnapKey` + 索引；
  - boot 时 `adopt_disk` / `adopt_disk_chains` 可从目录回填账。
- 但磁盘层当前只持久化**被卸载的** KV/快照；不会自动把“所有活跃链”落盘。
- `disk_dir` 当前是单目录；多模型必须改成按模型隔离的目录。
- `prefix_cache`、`disk_cache_mb`、`snap_disk_mb` 都是 profile 级配置；262k-vlm 档当前
  `prefix_cache = false`、磁盘层关闭。

### 2.4 不可直接恢复的进程内状态

| 状态 | 位置 | 能否 dump |
|---|---|---|
| CUDA graph / graph node / 图租约 | `GraphFleet` / `GpuCtx` | 否（指针、句柄、allocator 语义） |
| 设备 allocator / 池缓存 | `GpuCtx` / `cudaMallocAsync` | 否（地址不可重定位） |
| kernel registry / family runtime | `GpuServer` | 否（进程内对象） |
| 在飞 turn / 调度队列 / 锁 | `RunningEngine` / `actor` | 否（切换前排空） |
| tokenizer / chat template | worker host | 重新装载（不 dump） |
| RNG / 采样游标 | 请求内 | 不恢复 |

## 3. 状态分类：什么该 dump，什么不该

这是本功能最重要的边界。**“权重 dump”与“引擎状态恢复”必须分开设计**。

### 3.1 可恢复状态（Restorable）

| 状态 | 粒度 | 存放 | 说明 |
|---|---|---|---|
| 文本主干权重 | 每 rank、每张量 | 权重快照 | post-repack 最终设备块 |
| 视觉塔权重 | 每 rank、每张量 | 权重快照 | 塔是 Replicate，每 rank 一份 |
| DFlash2 / 草稿权重 | 每 rank、每张量 | 权重快照 | 草稿池独立 |
| rope 表 / 小常量 | 可选 | 重新生成 | 很小，v1 不进快照，减少格式面 |
| KV 链 | 链 / 块 | store 磁盘层 | P1；按模型目录隔离 |
| GDN 快照 | 槽 / 条 | store 磁盘层 | P1；现有 snap 腿可承载 |
| 前缀索引 | 链哈希 | store 磁盘层 | P1；boot 可 `adopt_disk_chains` |
| 会话元数据 | session | 小型 manifest | P1；语义需拍板（见 §15） |

### 3.2 不恢复状态（Ephemeral）

- 在飞 turn、排队 turn、采样中间态；
- CUDA graph / graph 池 / graph 捕获状态；
- GPU allocator 空闲池、scratch、pinned staging；
- kernel registry、family runtime、事件池；
- 设备指针、DMA 描述、stream/event 句柄；
- 当前请求的 RNG / stop 串 / 输出累积。

### 3.3 结论

- **P0 只做权重快照**：能直接满足“不重复 repack”。
- **P1 再做 KV / GDN / 前缀链休眠**：复用 store 磁盘层，不把 KV 塞进权重文件。
- **永不 dump 全 VRAM**：即使能写出 20GB，也无法在另一进程恢复图/指针语义。

## 4. 候选架构

### 4.1 方案 A：Supervisor + 单模型 worker（推荐）

```text
owl-server --models models.toml          # 轻量 supervisor，不碰 GPU
  ├─ 公共端口 :8080（HTTP 路由 / 管理端点 / 代理）
  ├─ worker(qwen)  : 内部 loopback 端口，单模型完整 server
  └─ 同一时刻只存在一个 worker（VRAM 只够一个）
```

切换序列：

```text
POST /v1/models/holo/activate
  -> supervisor 状态 = Draining
  -> 新请求返回 503 / Retry-After
  -> 旧 worker：停止接单，等待 active turn（超时精确 abort）
  -> 旧 worker：WeightCache::dump(weights)
  -> 旧 worker：可选 store hibernate（KV/GDN/前缀链）
  -> 旧 worker：SIGTERM / 优雅退出，释放 GPU 卡锁与显存
  -> supervisor 启动新 worker：
       -p <profile>
       --set runtime.bind=127.0.0.1:<ephemeral>
       --set cache.model_id=holo
       --set cache.dir=<state_root>/holo/weights
  -> 新 worker：读权重快照（命中则跳过 repack）→ 建池/图 → ready
  -> supervisor 原子切换代理目标
  -> 状态 = Serving(holo)，返回切换账
```

优点：

- GPU 上下文、图、allocator、kernel registry 随进程退出**结构性清空**，不会“热切换后越跑越脏”。
- 失败回退简单：目标起不来 → 重新起旧 worker（旧权重仍在缓存）。
- 与现有单模型 `server` 完全兼容：worker 就是现在的二进制；supervisor 是新增薄层。
- 多模型 profile 可以保留现有“单文件可复制”形态，不需要拆 `OwlConfig`。

代价：

- 切换期间有明确的**服务空窗**（旧已停、新未 ready），必须由 supervisor 统一回 503。
- 需要一个内部 worker 控制面（drain / dump / state）和 HTTP 代理。
- 不能做到“旧模型继续服务到新模型 ready”；VRAM 决定没有蓝绿。

### 4.2 方案 B：进程内重建 Engine

```text
actor_main
  loop {
    build Engine + load + run
    run_actor until Switch(model)
    shutdown_tp / drop
    rebuild target
  }
```

优点：没有进程启动、没有端口交接，理论上切换更快。

代价：

- 需要把 `RunningEngine` 的完整收尾路径显式化：图族、store、池、TP staging、GpuClient、
  GpuServer 线程、CUDA context、event 池、cublas 句柄、registry。
- 当前 `GpuClient` / `GpuServer` 的收尾更多是“进程退出兜底”，不是“同进程再起一份”的
  可重入路径；一个漏掉的句柄就会把第二次装载拖进 OOM/崩溃。
- 失败回退需要在同一进程里再拆一次；状态污染面比进程级大得多。
- 需要新增 engine generation / 全局资源生命周期约束，改动面远大于 supervisor。

**结论：不建议作为 v1。** 若将来确实需要“秒级、无进程切换”，再单独立项，作为方案 A 的优化阶段。

### 4.3 方案 C：exec 自重启

- 切换时写目标 profile，`execve` 自身，复用监听 fd。
- 实现最短，但监听 fd 继承、启动期请求、回滚、多个模型状态、日志都更脆弱。
- 失败时只能再 exec 一次，没有独立 supervisor 的观测面。

**结论：不作为主方案。** 可作为极端资源受限环境的降级模式。

## 5. 多模型配置与命名

### 5.1 建议形态：registry + 现有完整 profile

新增一个轻量 registry 文件，不改现有 profile 语义：

```toml
# models.toml
[server]
bind = "127.0.0.1:8080"
default_model = "qwen"
drain_timeout_secs = 120
switch_timeout_secs = 600

[models.qwen]
profile = "profiles/tp27b-3080-262k-vlm.toml"
aliases = ["qwen3.8-27b", "qwen"]
state_dir = "/var/lib/owl/models/qwen"

[models.holo]
profile = "profiles/holo-3.1-35b-fp8.toml"
state_dir = "/var/lib/owl/models/holo"

[models.gguf]
profile = "profiles/legacy/gguf27b-262k.toml"
state_dir = "/var/lib/owl/models/gguf"

[weights_cache]
dir = "/var/cache/owl/weights"
max_gb = 64
mode = "auto"          # off | read | write | auto
verify = "manifest"    # manifest | hash
```

规则：

- `profile` 仍是完整单模型档；registry 只负责“有哪些模型 / 默认是谁 / 状态目录”。
- `runtime.bind` 在 worker 启动时由 supervisor 覆盖为内部地址；公共端口只由 supervisor 持有。
- 每个模型必须有独立 `state_dir`，禁止两个模型共享 KV/前缀缓存目录。
- 模型名取 registry key；`[server].model_name` 只作缺省显示名，不参与路由。
- 启动时逐个 profile 做**静态预检**（parse + `--check` 级别），不加载权重；
  任何一个 profile 非法 = supervisor 拒启（不静默跳过）。
- 共享约束只校验“无法在 worker 内独立解决”的项：公共端口、state 目录不重叠、缓存目录可写。
  TP 卡位、量化、上下文、视觉/spec 允许每个模型不同——同一时刻只有一个 worker 占卡。

### 5.2 为什么不是“单文件 `[[models]]` 共享硬件段”

那需要把 `OwlConfig` 拆成“站点/硬件公共段 + 模型段”，并重做所有 profile 的 merge 语义。
提案阶段不引入这个重构；registry + 完整 profile 的迁移成本最低，也保留现有单档启动方式。

## 6. 管理面 API

按用户裁决：**只允许显式管理端点**；chat 请求的 `model` 字段不触发自动切换。

### 6.1 `GET /v1/models`

返回配置中的全部模型：

```json
{
  "object": "list",
  "active": "qwen",
  "switching": false,
  "data": [
    {
      "id": "qwen",
      "object": "model",
      "owned_by": "owl",
      "aliases": ["qwen3.8-27b"],
      "status": "active",
      "generation": 7,
      "profile": "profiles/tp27b-3080-262k-vlm.toml",
      "capabilities": {"vision": true, "spec_depth": 7, "max_seq": 262144}
    },
    {
      "id": "holo",
      "object": "model",
      "status": "standby",
      "last_error": null
    }
  ]
}
```

状态机取值：

```text
standby | draining | dumping | stopping | loading | warming | active | error
```

### 6.2 `POST /v1/models/{id}/activate`

请求：

```json
{"wait": true, "force": false}
```

语义：

- `wait=true`（缺省）：阻塞到目标 `active` 或超时；返回完整切换账。
- `wait=false`：返回 `202 + job_id`，由 `GET /v1/models/{id}/status` 轮询。
- 同模型：`200` no-op，`generation` 不变。
- 已有切换在跑：`409 model_switch_in_progress`。
- `force=true`：跳过排空等待，直接取消活跃 turn（仍走 dump）；默认 false。
- 切换失败：`502 model_switch_failed`，带 `from` / `to` / `phase` / `error` / `rollback`。

响应示例：

```json
{
  "ok": true,
  "from": "qwen",
  "to": "holo",
  "generation": 8,
  "drain_ms": 1200,
  "dump_ms": 8300,
  "stop_ms": 700,
  "load_ms": 9100,
  "warmup_ms": 2400,
  "weights_cache": "hit",
  "kv_cache": "hit",
  "bytes": {"weights": 21474836480, "kv": 4294967296}
}
```

### 6.3 `GET /health` / `GET /ready`

- `/health`：supervisor 存活 + 当前状态；即使模型加载中也返回 200，但 body 明确状态。
- `/ready`：只有 `active` 且 worker ready 才 200；否则 503。
- `/v1/chat/completions` 在 `draining/dumping/stopping/loading/warming` 期间返回：

```json
{"error": {"type": "model_switching", "message": "...", "active_model": "qwen", "target_model": "holo"}}
```

并带 `Retry-After`。

### 6.4 显式拒绝自动切换

chat 的 `model` 字段：

- 省略或等于 active：正常；
- 是已配置但非 active：`409 model_not_active`，body 给出 `activate` 端点；
- 未配置：`404 model_not_found`。

这样客户端不会因为一次普通请求意外触发 20 秒的模型切换。

## 7. 切换状态机与在飞请求

### 7.1 状态机

```text
Serving(old, gen)
  -> Draining(old)
  -> Dumping(old)
  -> Stopping(old)
  -> Loading(new)
  -> Warming(new)
  -> Serving(new, gen+1)

任一步失败
  -> Failed(new)
  -> Rollback(old)  (可选)
  -> Serving(old, gen) 或 Failed
```

约束：

- 全局唯一 switch 锁；同一时刻只有一个 `Draining..Warming`。
- 状态转换只由 supervisor 写；worker 只上报自己的 ready / draining / error。
- 每次切换递增 `generation`；日志、指标、会话键都带 generation。

### 7.2 排空（drain）

1. supervisor 停止向旧 worker 转发新 chat 请求；新连接直接 503。
2. 旧 worker 内部 `POST /internal/drain`：
   - 停止接受新 turn；
   - 让 active turn 自然完成；
   - 到 `drain_timeout_secs` 后，对剩余 turn 逐个 `EngineReq::Abort`（复用现有精确取消面）；
   - 返回 `(drained, aborted, remaining)`。
3. 若仍有 turn 未退出，supervisor 进入 `force` 分支：SIGTERM worker；
   再超时则 SIGKILL；记录 `forced_abort`。
4. 只有排空完成才允许 dump 权重；否则 D2H 会与在飞 kernel 竞争，且权重可能被覆盖/图仍持有租约。

### 7.3 新请求

| 时刻 | 行为 |
|---|---|
| `Serving(old)` | 正常转发 |
| `Draining/Dumping/Stopping` | 503 `model_switching` + Retry-After 1s |
| `Loading/Warming(new)` | 503 `model_loading` + Retry-After 2s |
| `Serving(new)` | 正常转发 |
| `Failed` | 503 `model_unavailable`，body 给 last_error |

管理端点本身始终可用（除 supervisor 退出）。

## 8. 权重快照设计（P0 核心）

### 8.1 快照对象

只快照**最终设备块**，不碰源文件、不碰 KV：

- 文本主干：`wt.<key>` / `repack.<key>`；
- 视觉塔：`wt.<key>`；
- DFlash2 / 草稿：`wt.<key>` / `repack.<key>`；
- 可选：lm_head int8 的 `i8q` / `i8s`（如果它们已是最终块）；
- 不快照：rope 表、staging、graph、池、GDN、KV。

### 8.2 目录与格式

```text
<weights_cache.dir>/<model_id>/<fingerprint>/
  manifest.json
  rank0.bin
  rank1.bin        # TP2；单卡只有 rank0
  COMPLETE         # 最后写入的空标记（原子提交）
```

`manifest.json`：

```json
{
  "format": 1,
  "engine_build": "git:.../dirty:false",
  "model_id": "qwen",
  "model_fingerprint": "sha256:...",
  "load_fingerprint": "sha256:...",
  "created_unix_ms": 1790000000000,
  "ranks": 2,
  "tensors": [
    {
      "rank": 0,
      "key": "layers.0.self_attn.q_proj.weight",
      "block": "repack.layers.0.self_attn.q_proj.weight",
      "kind": "device_rearrange",
      "dtype": "U32",
      "shape": [5120, 4096],
      "offset": 0,
      "bytes": 10485760,
      "xxh3": "..."
    }
  ]
}
```

规则：

- 每个 rank 一个连续 `.bin`，4 KiB 对齐；`dtoh` / `htod` 可按 `offset/bytes` 直读写。
- `kind` 决定恢复时的分配方式：
  - `direct` / `transposed` → `wt.<key>`，按 `dtype`；
  - `device_rearrange` → `repack.<key>`，`U32`；
  - 其他未来臂必须新增 kind 并更新恢复分派，未知 kind = 缓存拒用（不猜）。
- manifest 先写临时文件，`fsync`，`rename`；`rank*.bin` 全部 `fsync` 后才写 `COMPLETE`。
- 缺 `COMPLETE` / 任一文件大小不符 / manifest 解析失败 = 缓存 miss，删除半成品。

### 8.3 指纹

`model_fingerprint` 不直接对 20GB 权重做全量哈希（启动太慢），默认用**源元数据指纹**：

- `config.json` 内容哈希；
- safetensors index / GGUF header 的关键字段；
- 每个源文件的 `(size, mtime)`；
- 量化方案、`model.kind`、`model.quant`、`head_quant`、`vision`；
- 可选 `verify = "hash"` 时做全量内容哈希（慢，排障/审计用）。

`load_fingerprint` 覆盖**会改变最终设备块**的装载事实：

- `engine_build`（二进制版本 / kernels asset 版本）；
- `slice_id` / `shard` / TP world；
- `tp_vocab_split`；
- `dtype` / 激活 dtype；
- `device_repack` 路径；
- `model.rope`（如果按 max_seq 改变 rope 表，虽然 v1 不缓存 rope，但避免误命中）；
- `vision`；
- `spec` / 草稿目录指纹（如果草稿权重也进同一快照）。

任一不匹配 = miss，不尝试“部分复用”。

### 8.4 装载钩子

目标：**cache hit 不进入 `load_direct` / `load_device_rearrange` / `load_transposed`**。

在 `load_group` 的臂分派前加一条显式路径：

```text
load_group(face, group, src, ...)
  for w in group:
    if let Some(entry) = cache.restore(face, w)? {
        w.sink.deliver(entry.block)
        manifest.push(entry)
        continue
    }
    normal arm...
    cache.record(entry)   // 只记录，不立即写盘
```

恢复动作：

1. 按 `w` 计算 cache key（key + kind + dtype + shape + shard）；
2. 查 manifest；
3. 按 kind 分配目标块（`wt.*` / `repack.*`）；
4. 从 `rankN.bin` 读入 pinned buffer；
5. `htod` 到目标块；
6. 构造 `LoadEntry`（带 cached csum），交给原 `sink.deliver`。

注意：

- `LoadStaging::plan` 仍会调用 `src.native_dtype` / 形状元数据；这是元数据读取，不是权重读取；
  若某些源实现需要打开文件，成本可接受；不为了缓存绕过整个 `WeightSource`。
- `LoadOpts` 当前 `Copy`；引入 `Option<Arc<WeightCache>>` 后需改为 `Clone`，并逐个更新约 35 个
  构造点。这是 P0 的主要机械改动面，提案阶段先记录，不施工。
- cache 必须按 rank 隔离；TP2 两个 worker rank 各写自己的 `rankN.bin`，不要合并成一个文件。

### 8.5 dump 时机

推荐 **hibernate 时 dump**，不在每次冷启动后立即写：

- 冷启动没有缓存 → 正常装载；首次切走时 dump；
- 切回命中 → 直接用缓存；
- 运维正常 `SIGTERM` 停止时，如果 `weights_cache.mode` 允许，也可走同一 dump 路径；
- `mode = "off"` 完全关闭；`read` 只读不写；`write` 只写不读（调试）；`auto` 读写。

dump 流程：

1. 确认已 drain / worker 不再跑 turn；
2. `face.sync()`；block ledger 检查目标权重块仍在场；
3. 逐 rank / 逐张量 `dtoh` 到 pinned buffer，顺序写 `.bin`；
4. 计算 XXH3；写 manifest；
5. `fsync` + `COMPLETE` + 目录 `fsync`；
6. 返回字节数、耗时、失败张量列表（失败 = 整个快照不提交，不写 `COMPLETE`）。

### 8.6 为什么不是全 VRAM 镜像

- CUDA graph 节点里存的是**设备地址**；换进程后地址不同，图不可重放。
- `cudaMallocAsync` 的池元数据、VMM 映射、event/stream 句柄都是进程/上下文私有。
- 直接写 20GB 再读回，除了权重还要恢复 allocator 布局；这等于重写 CUDA 运行时。
- 权重快照只依赖 `htod`/`dtoh`，是当前 `DeviceClient` 已经验证过的路径。

## 9. KV / GDN / 前缀链休眠（P1）

### 9.1 原则

- **按模型隔离**：`state_dir/<model_id>/store/{kv,snap}`；不同模型的链哈希即使碰撞也不共享。
- **只持久化 durable 状态**：活跃 turn 的临时 KV 不需要跨切换；前缀链 / GDN durable snapshot 才值得。
- **不把 KV 塞进权重文件**：生命周期、预算、驱逐策略完全不同。
- **恢复失败可降级**：KV miss 只是 TTFT 变差，不是启动失败。

### 9.2 需要补的能力

当前 store 磁盘层支持 `plan_offload` / `commit_spill` / `adopt_disk`，但没有“把当前所有
durable 链一次性落盘”的 hibernate 入口。P1 需要：

1. `Rel::hibernate()`：
   - 遍历活跃链，按链尾→链头顺序 spill（复用 §14.6 链级卸载律）；
   - durable GDN 快照逐条 offload；
   - 写 chain index / snap index；
   - `fsync`；
   - 返回 `(chains, kv_bytes, snaps, snap_bytes, skipped_transient)`。
2. `Rel::resume()`：
   - boot 时用 `adopt_disk` / `adopt_disk_chains` 回填；
   - 校验模型 fingerprint / 几何 / dtype；不匹配 = 隔离并清空，不静默使用。
3. `SessionBank` 元数据：
   - session id、token 历史 / 哈希、链哈希、GDN 快照 key、创建 generation；
   - 存 `sessions.json`（原子写）；
   - 恢复时只恢复“模型 fingerprint 匹配 + 链内容在场”的会话；
   - 是否允许同 session id 跨模型继续，见 §15 待拍板。

### 9.3 预算

- 262k 主 KV fp8 ≈ 4G；草稿 BF16 ≈ 2.5G；GDN 快照按 `snap_max`。
- 休眠会把“本来在显存/宿主”的 KV 写到磁盘；需要给每个模型独立磁盘配额：
  - `weights_cache` ≈ 21G/27B 两 rank；
  - KV 休眠 ≈ 4–7G/模型；
  - 多模型同时保留会线性增长。
- 建议默认：**权重缓存开，KV 休眠关**；262k 档按需开，且设置 `max_gb` 与 LRU。
- 磁盘满：跳过 KV dump，只保证权重 dump；日志 WARN；切回时 KV miss。

### 9.4 会话语义（建议）

- session key 改为 `(model_id, session_id)`；
- 切换后，旧模型的 session 不活跃；客户端用同一 `session` 打新模型：
  - 默认 `409 session_model_mismatch`，要求显式新 session 或 reset；
  - 若 P1 恢复了该模型 session，且 fingerprint 匹配，可继续。
- 不把旧模型的 tokenizer/KV 拼到新模型上。

## 11. 失败、回退与缓存自愈

| 故障 | 处理 |
|---|---|
| 目标 profile 预检失败 | supervisor 拒启该模型；切换请求 400；旧模型保持 active |
| 目标 worker 启动失败 | 标记 `error`；若 `rollback=true`，从旧模型缓存重启旧 worker；否则 503 |
| 权重快照 manifest 损坏 | 删除该 fingerprint 目录；回退全量装载；记录 WARN |
| 权重快照某张量校验失败 | 整个快照拒用；回退全量装载；不部分恢复 |
| dump 中途磁盘满 | 不写 `COMPLETE`；保留旧快照；切换继续（目标仍可全量装载） |
| worker dump 时崩溃 | 临时目录残留；下次启动清理；旧快照不受影响 |
| worker 加载时崩溃 | supervisor 捕获 exit code；回退旧模型或 `Failed` |
| SIGTERM 不退出 | 超时 SIGKILL；GPU 卡锁由锁文件 live-pid 机制回收 |
| 并发切换 | 全局锁；第二个请求 409 |
| supervisor 崩溃 | worker 设 `PDEATHSIG`；systemd 重启 supervisor；启动时清理孤儿 worker |
| 缓存目录不可写 | 降级为无缓存；启动/切换继续；WARN 一次 |

回退原则：

- 旧模型在停止前已经 dump，回退不需要重新 repack；
- 回退也走同一个 worker 启动 + 权重缓存路径，不写第二套逻辑；
- 回退失败 = 明确 `Failed`，不把端口指向死 worker。

## 12. 性能与容量预算

### 12.1 目标（提案值，施工后用实测替换）

| 指标 | 目标 |
|---|---|
| 27B 权重 dump（两 rank） | < 20s（顺序写，受磁盘带宽限制） |
| 27B 权重 restore（两 rank） | < 15s（命中，无 repack） |
| worker 启动 + 池/图 warmup | < 15s |
| 端到端切换（权重-only） | < 45s；目标 25–35s |
| cache hit 的 repack 次数 | **0**（指标/日志可证） |
| 切换后 GPU 残留 | 0 个 compute app / 0 MiB 池残留 |

### 12.2 关键测量

- `swap.dump_ms` / `swap.load_ms` / `swap.stop_ms` / `swap.warmup_ms`；
- `swap.bytes.weights` / `swap.bytes.kv`；
- `swap.cache.weights` = `hit|miss|corrupt`；
- `swap.repack_skipped`（cache hit 时必须 >0）；
- `load.repack` 指标在 cache hit 路径必须为 0；
- 切换前后 `nvidia-smi --query-compute-apps`、块账、`/debug/vram`；
- 输出对拍：同一 prompt 在 cold load 与 cache restore 下 token 逐位一致（greedy）。

### 12.3 磁盘预算

```text
27B 权重快照：2 × ~10.5G = ~21G
KV 休眠：~4–7G/模型（可选）
临时 dump：同量级（写临时文件后 rename）⇒ 峰值约 2× 快照
```

建议 `weights_cache.max_gb` 至少 64G；低于 2×27B 时只保留最近一个模型。

## 19. 结语

这个功能的难点不在“把权重拷进拷出”，而在**生命周期边界**：

- 权重可以快照；
- KV/GDN/前缀链可以通过 store 磁盘层休眠；
- 但 CUDA 图、设备指针、allocator、kernel registry、在飞 turn 不能快照。

因此提案推荐把“模型切换”放在**进程边界**上解决：supervisor 负责状态机和路由，worker 负责单模型
完整生命周期；权重快照负责跳过 repack；store 磁盘层负责可选的会话/前缀休眠。
这样可以把最危险的部分交给操作系统和进程退出，而不是在同一个 CUDA context 里反复拆装。
