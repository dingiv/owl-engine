# 图像窗口旋转（Visual Window Rotation）—— 设计与施工

> 2026-10-20 立项。定位:**agent 循环里"只保留最近 N 张截图"的显存/前缀缓存解法**。
> 一句话:**不重算,把已经算过的 KV 在位置空间里滑一格**。
>
> 前置(不在本设计范围):引擎/服务面的图片接线(`Vlm` 装配已在 models 层完成,
> 见 `docs/arch/vision-tower-设计与CPU对拍.md` 的 M4/M5;服务端 `image_url` 入口尚未接线)。

| 修订 | 内容 |
|---|---|
| 2026-10-20 首轮 | 立案:语义边界、m-RoPE 位置几何、页表置换 + Δ-RoPE 算法、记账、门与分阶段 |

## 0. 结论速览(TL;DR)

1. **做法**:会话固定一块"视觉尾窗"(`N` 个等长槽,页对齐;`N ∈ [1,8]`,**会话内冻结**),
   每步新截图**覆写最老槽**;
   保留的槽**token 不变**,逻辑页序做一次**循环置换**;窗口基址随 `P` 的页对齐增长整体右移
   (被搬动的槽共用**一个标量** Δ),并对这些槽的 K 乘一次**增量旋转** `R(Δ)`。
2. **每步成本**:(`N−1`) 槽 × `L` tok × 16 全注意力层 × 1 KiB;`N=3` 时 ≈ **40 MiB/rank 读写**
   ≈ **0.1–0.3 ms**(`N=8` 时 ≈ 7×)
   (含命令往返)。
3. **每步收益**:省掉 `N−1` 张图的 prefill((`N−1`)·L tok;N=3、L≈1000 ⇒ 2 000 tok ≈ 1.1–1.4 s @1780 t/s)
   + 省掉视觉塔对这些图的重复编码(0.1–0.2 s/图);
   - **网格由服务端预处理固定**(不依赖客户端分辨率),见 §4.1/§7。
   ⇒ **收益/成本 ≈ 10³–10⁴ 量级**;真正的代价在**近似语义**与工程实现,不在 GPU 时间。
4. **语义边界(必须先认账)**:被保留图的 K/V 是在"还看得见被淘汰图"时算出来的 ⇒
   旋转是**搬运记忆**,不是"重算成只见过 N 张图的短上下文"。等价性只在
   "没有淘汰(纯平移)"时成立(§8 G1a)。
5. **hybrid 约束**:本模型 48 层 GDN + 16 层全注意力。GDN 是循环态、**不能倒带** ⇒
   旋转只作用于 16 个注意力层的 KV;**GDN 状态保留全史**(默认,等价于"长期记忆"),
   要"严格只记得 N 张"只能重算 GDN(退回全量重算,本设计不提供)。

## 1. 问题与目标

GUI agent 每步产生一张新截图,业务侧把上下文裁到"只保留最近 N 张"。裁掉的是**中部**内容:

- 之后所有 token 的**位置前移**,内容也变;
- 因果注意力下,断点之后的 KV **全部作废**;
- 图是 token 大户(≈1.3k/张) ⇒ 每步重灌 "N 张图 + 之后的文本",20k 历史 @1400 t/s ≈ 14 s/步。

目标:**每步只付"新图 + 问题"**(≈1.6k tok),与历史长度、窗口大小解耦;
且**稳定前缀(系统提示 + 文本历史)的 KV 永不受影响**。

## 2. 语义(先定罪,再施工)

### 2.1 旋转 = 搬运,不是重算

KV 是**上下文相关**的:`K,V = f(hidden)`,`hidden` 又依赖当时能看见的全部前缀。
被保留那张图在"看得见旧图"时算出的 K/V,搬过去之后仍然带着旧图的影响。
所以:

- **对"从现在起"的 token**:完全正确(它们看到的是旋转后的完整窗口);
- **对"已经算过的 token"**:不回改(因果律)。

这与"记笔记"同构:你写下一条规则,你之前的思考没有它,从下一句话起按它办。

### 2.2 GDN 的边界

48 层 GDN 没有 KV,只有一份**当前循环态**;它已经在热区尾部,无法"插入/倒带"。
本设计的处理:**GDN 状态原地不动**——窗口只影响 16 个全注意力层。
业务上的含义:模型仍"记得"更早的截图(通过 GDN),但注意力层只看最近 N 张。
若业务要求"严格只记得 N 张",只能重算 GDN(= 放弃本设计)。

### 2.3 位置几何(m-RoPE,已核对代码)

Qwen3.5 系用 3D m-RoPE(`crates/models/src/layers/mrope.rs`):

- 文本段:`pos = cur + k`,三网格同值;
- 图像段(单张,网格 `(t,h,w)`,merge=2):逐 token
  `pos = [cur, cur + hi, cur + wi]`(h-major),段末 `cur += max(h,w)/merge`;
- 频率维按 `sections = [11,11,10]` **交错**认网格,rotate-half 核直吃 `[L, half]` 行表。

**关键推论**:图像 token 的三个分量都以 `cur` 为锚 ⇒ 把一张图整体挪到新的 `cur = cur + Δ`,
等价于**三个分量同加 Δ** ⇒ 重转 K 只需要**一个标量 Δ**(不是逐维/逐网格的表)。
这让"重转"退化成一次普通 rope,直接复用现役表驱动核。

## 4. 布局契约

```
位置: [ P: 系统提示 + 文本历史(append-only) ][ S0 ][ S1 ][ S2 ][ Q: 本轮问题 ][ 生成 ]
                                              ↑ base = len(P)     每槽 L tok,页对齐
```

### 4.1 槽长与网格(服务端预处理,不依赖客户端)

1. **槽等长**:每槽 `L_slot` 个 token,`L_slot % 32 == 0`(页大小 32 tok)。
   `L_slot = ceil(L_img / 32) · 32`,其中

   ```
   L_img = t · (h / merge) · (w / merge)        # merge = 2;单图 t = 1
   ```

   `L_img` 之后的 **pad 尾巴**(≤31 tok)用**固定字符**(建议 `\n`),属于该槽的 token 段,
   跟着槽一起旋转。
2. **网格由服务端定,会话内冻结**:引擎/适配层对每张图做
   `smart_resize`(Qwen-VL 同口径:factor = patch×merge = 32,min/max_pixels)
   后 **letterbox 到会话网格** `(h, w)`;会话网格 = **首图**定下的网格
   (可被请求显式指定)。pad 比例 >10% 打 metric 告警(分布风险)。
   ⇒ `L_img`、`A` 在整个会话里恒定,**不依赖客户端分辨率**。
3. **推进量恒定**:每槽 m-RoPE 推进量 `A = max(h,w)/merge` 相同
   ⇒ 窗口之后的 `cur` 不随"换哪张图"变化 ⇒ `Q` 与文本的位置稳定。
4. **窗口在最尾**(`Q` 之前):`P` 的 KV **完全不依赖窗口内容** ⇒ `P` 纯 append-only,
   稳定前缀缓存 100% 命中,旋转碰不到它。
5. **`P` 只追加、且按页对齐**:每轮文本增量(pad 到 32 tok 的倍数)写进 `P` 尾部。
   - 窗口基址随 `P` 增长右移 ⇒ 页对齐让移动正好是**整数页**,无半页;
   - 上一轮输出 `A_t` 要**重放到 `P` 尾部**(位置变了)⇒ 每轮多 prefill 50–200 tok;
   - **需要 agent 显式开启该能力**(§8.5);未开启 = 引擎不建窗口状态、走普通路径。

### 4.2 `N`:1..8,会话内冻结

- 请求面给 `window.slots = N`(`1..8`),**会话首个请求定死**,后续请求变更 = **响亮拒(400)**;
- `N = 1` = 无保留槽(每步整窗覆写,旋转退化为空操作);
- 窗口占页 = `N · L_slot / 32`,**按需增长**到 `N`(见 §4.3),之后循环复用;
  `N=8, L≈1024` ⇒ 8 192 tok ⇒ 设备 KV ≈ 256 MiB/rank(f16),可接受。

### 4.3 预热:`N_eff` 从 1 长到 N(不预付空槽)

会话开始时按"见过的图数"逐步长窗口,避免上电就 prefill 8 个空槽:

```
第 1..N 张图:  N_eff += 1,新槽**追加在右侧**(已有槽的位置不变,Q 右移)
之后:          N_eff = N,每步 = 3-循环置换 + Δ(§4.2/§5.2)
```

- 增长期**不需要旋转**(已有槽位置不动),只需为新槽 prefill;
- `N = 1` ⇒ 永远"整窗覆写",无旋转、无 Δ;
- 增长期的 `Q` 位置每步变,但 `Q` 本来就是新 token(**必然重 prefill**),无额外成本。

### 4.4 每步的 Δ(唯一的一个标量)

设上一步窗口基址 `base_old`、本步 `base_new = len(P_new)`;保留的 `N−1` 槽从
`base_old + (i+1)·L_slot` 挪到 `base_new + i·L_slot`(`i = 0..N−2`):

```
Δ = (base_new - base_old) - L
```

- `base_new - base_old` = 本步追加进 `P` 的文本长度(**按页对齐后** = `32·g`,
  含上一轮输出 `A_t`、本轮动作/观察文本);
- 被搬动的 `N−1` 槽共用同一个 Δ;
- 每步在 host 上算一次即可(整数,无浮点误差累积)。

> 若 `P` 不增长(`Δ = -L`),就是纯粹的"整槽前移一格"。

## 5. 算法

### 5.1 识别与匹配(两种接口形态)

- **显式形态(推荐先做)**:请求带**能力开关 + 窗口规格**

  ```json
  "window": {
    "enabled": true,          // 不写/ false ⇒ 引擎不建窗口状态,走普通路径(§8.5)
    "slots": 3,               // 1..8;会话首个请求定死,之后变更 = 400
    "grid": [80, 50]          // 可选:会话网格(patch 网格);缺省由首图 smart_resize 决定
  }
  ```

  引擎按规格切块,**不需要猜**。
- **自动形态(后续)**:按 `image_token`(248056)的连续段识别 image span,
  用**图片字节哈希**匹配上一轮的槽位 ⇒ harness 完全无感(它怎么淘汰都行,
  只要它还在发图而不是占位符)。

### 5.2 页表 3-循环置换(零数据搬运)

设窗口页段为 `W = [P0 | P1 | … | P(N−1)]`,每段 `L_slot/32` 页:

```
新逻辑 S_i     ← 旧 P_i 的物理页(原 S_{i+1})        i = 0..N−2
新逻辑 S_{N−1} ← 旧 P_{N−1} 的物理页(原 S0,马上被新图覆写)
```

- **不拷贝、不分配、不释放**:三层循环置换;
- 写回会话块表并 `write_bt`(内容重写,图不重捕);
- 被覆写的那组物理页里,旧图的 K/V 直接作废(新图 prefill 会全量写)。

### 5.3 重转 K(唯一的新数学)

对**被搬动的 `N−1` 槽**(合计 `(N−1)·L_slot` token)的 K 乘 `R(Δ)`:

```
K' = K·cosΔ + rotate_half(K)·sinΔ
cosΔ_j = cos(Δ · θ_j),  sinΔ_j = sin(Δ · θ_j),  θ_j = inv_freq[j]
```

- `Δ` 是标量(§2.3 推论)⇒ delta 表只有**一行** `[half]`,广播到 `(N−1)·L_slot` 行;
- **V 不动**(V 无位置);
- **零新数学,一个 API 包装**:现役 `SemanticKernel::Rope` 核本身就吃外部 cos/sin 表
  (`Rope::forward_k(k, pos, …)` 的表来自层内),但 `forward_k` 只按 `pos` 取层内表;
  需要加一个**显式表入口** `forward_k_with_tables(k, cos, sin, …)`(直接喂 delta 表,
  零新核、零新语义)。K 池按页连续(kNHD,页内 32 tok 连续)⇒ 可用 `of_block(..)`
  建 `[(N−1)L, hkv·hd]` 视图;若核只支持 out-of-place,用一块 scratch
  (`(N−1)L×16层×1 KiB`;N=3、L=1280 时 ≈42 MiB)往返;
- 数据量:`(N−1)L × 16 层 × (hkv·hd·2B)`;N=3、L=1280、hkv=2、hd=256 ⇒ **40 MiB/rank**;
- fp8 KV:**先 dequant→rotate→quant**(或窗口区强制 f16)。1M 档是 f16,不受影响。

### 5.4 新图与问题

- 新图:S2 槽位,**只跑视觉塔 + 该槽的 prefill**(位置表 = 本步 `rope_index` 的 S2 行段);
- `Q`:接在窗口后正常 prefill;
- `P`:**零 prefill**(整链命中)。

### 5.5 每步命令序(顺序即语义)

```
⓪ prefill:  P 的文本增量(上一轮 A_t + 本轮文本,pad 到 32tok 整),接在 P 尾部
① host:      Δ = (base_new - base_old) - L;Δ 表 [half] → 广播成 [2L, half]
② write_bt:  新页序(3-循环置换 + 窗口基址右移 g 页)写进会话块表   ← 内容重写,图不重捕
③ re-rope:   对 S0..S(N−2)(被搬动的 N−1 槽)的 K 乘 R(Δ)  ← 16 层批量,同 COMPUTE 流
④ (视觉)     新图 → tower_forward(只这一步跑塔)
⑤ prefill:   S2 的 L 个占位 token(位置表 = 本步 rope_index 的 S2 行段)
⑥ prefill:   Q(接窗口之后);然后正常 decode
```

顺序纪律:
- ②③ 必须在 ⑤ 之前(⑤ 的注意力要读旋转后的 K 与新区块表);同 COMPUTE 流,天然有序;
- ③ 只写 K 缓冲,不碰 V/池句柄/图;
- 全程**无** `GraphBegin/GraphEnd`,也**无** `mem_pool_trim`(避免两 rank 异步)。

### 5.6 图与命令纪律

- 禁止 `GraphBegin/GraphEnd`(不重捕);只发 `write_bt`(一条)+ re-rope(批量一条)+ prefill;
- TP2:两 rank 对称执行同一置换与同一 Δ 表(不引入 rank 间差异)。

## 6. 记账(store / KVMem)

| 对象 | 处置 |
|---|---|
| 窗口页(S0..S2) | **不进缓存树、不注册链**(= 快照腿 `Transient` 的等价语义):每步内容都会变,登记进树只会产生碎条目;同时**不下沉、不被选择层召回**(它们是热面) |
| `P` 的链 | 正常注册;`match_prefix` 只走 `P`(独立链根) |
| 旋转后的页内容 | 哈希失效(内容变了)⇒ 必须不进树(Transient 天然满足) |
| 宿主腿 | 窗口页常驻设备(热);宿主腿只服务 `P` 与历史 |
| 快照 | 窗口**不打 GDN 快照**(它每步都变);`P` 的边界快照照旧 |

**链根独立**是前置(与双槽共用同一件基元):`register_chain/match_prefix` 需要
"从某个位置基址开始的独立链",否则 `P` 的树路径会穿过窗口而失效。

## 7. 视觉侧(含服务端预处理)

### 7.1 预处理(网格由服务端定,不信客户端)

1. 解码图片 → RGB;
2. `smart_resize`(Qwen-VL 同口径:factor = `patch×merge` = 32,min/max_pixels
   由 `config.json` 的 processor 配置取);
3. **letterbox** 到会话网格 `(h, w)`(保持长宽比;pad 用固定色,建议黑);
   **会话网格 = 首图**定下(或请求 `window.grid` 显式给),会话内冻结;
4. 记 metric:`window.pad_ratio`(pad 面积占比);>10% 告警(分布风险);
5. 归一化后的字节算 **SHA-256** ⇒ 去重键(原始分辨率不同、归一化后相同也算同图)。

> 为什么必须服务端做:客户端分辨率不可控;而 `L_img`/推进量 `A` 必须恒定,
> 否则窗口之后的 `Q` 与文本位置漂移(§4.1)。

### 7.2 塔与去重

- 每步**只对新图**跑视觉塔(`Vlm::tower_forward`),保留图**不重编码**(它们的 KV 被搬);
- 新图的 merged 行数必须 = 该槽占位 token 数(现成断言在 `Vlm::inputs`);
- 图片哈希(**归一化后**)可做**跨步去重**:若新图与窗口中某槽字节相同,
  直接复用该槽的 KV(连塔都不用跑);
- 视觉塔自身的 KV/中间量不进 KVMem(塔是一次性前向)。

## 8. 门(判据)

| 门 | 判据 | 说明 |
|---|---|---|
| **G1a 机械等价** | "无淘汰(只按 Δ 平移、内容不变)"时,**旋转 vs 全量重算逐位一致**(logits `max\|Δ\| = 0`) | 验证 Δ 表、置换、bt 重写的正确性 |
| **G1b 近似漂移** | 有淘汰时:同一输入,旋转 vs 重算的 top-1 一致率、`cos`,**只作监控不作硬门** | KV 语义上不等价(§2.1),必须如实记录 |
| G2 命中 | 每步 `cached_tokens` 增量 = 新图 + `Q`;`P` 的块命中 ≈100% | `/debug/vram` + 服务面 usage |
| G3 延迟 | 每步 TTFT ≈ `1.6k tok` 的 prefill;旋转段 ≤ 1 ms | 与 C 对照 |
| G4 任务 | 真 GUI harness A/B:成功率不塌 | 业务门,样本要够 |

### 8.5 能力开关与兜底(agent 必须显式开启)

**开关**:请求带 `window.enabled = true` 才启用。未开启 ⇒ 引擎**不建窗口状态、不旋转**,
按普通请求处理(链路零开销)。

**契约校验(每轮,引擎自己做,不依赖 agent 自觉)**:

| 校验 | 失败时 |
|---|---|
| `P_new` 以 `P_prev` 为前缀(模板前缀比对) | **契约破裂** ⇒ 清窗口状态 + 本轮按 **C(重算窗口)** 处理 + WARN + metric `window.contract_violation` |
| 本轮图片 span 数 ≤ `slots` | 只用最后 `slots` 张(与 harness 语义一致)+ metric |
| `slots` / `grid` 与首轮一致 | **400 响亮拒**(几何冻结) |
| 每个 image span 长 = `L_img`,段后 pad 数一致 | **400**(槽几何不符;agent 侧拼装错) |

**兜底原则**:能力声明了但契约破了 ⇒ **宁可重算,不许静默错值**;
未声明 ⇒ 完全不进这套逻辑(不影响其它 agent)。

## 10. 风险与不做的事

**风险**

1. **m-RoPE 位置簿记**:`cur` 推错会静默错位 ⇒ P3 必须用 `MropeCfg::rope_index` 的
   全表对拍(逐元素),而不是只看输出文本;
2. **绕过预处理**:任何一图未走 `smart_resize + letterbox`(直接喂原图)⇒ `L_img`/`A` 变,
   `Q` 与文本位置漂移 ⇒ 必须由引擎侧统一预处理(§7.1),`window` 路径**不接受**外部已编码的 token 段;
3. **GDN 近似**:窗口外记忆仍影响生成(默认),业务需 A/B 确认可接受;
4. **fp8 K**:需 dequant/requant 变体,或窗口区强制 f16;
5. **harness 裁剪文本历史**:`P` 不再是 append-only ⇒ 命中率塌,退化为 C。

**不做(明确挂账)**

- 不重算 GDN(因此不提供"严格 N 图"语义);
- 不做跨槽内容搬移的**真实拷贝**路径(等长槽 + 逻辑置换已够;不同长度才需要拷贝);
- 不做窗口页的宿主下沉/选择召回(它们是热面);
- 不与双槽的"冷区插入"混用(两件事正交,但各自的记账面要先各自干净)。

## 11. 与双槽 / notebook 的关系

| | 图像窗口旋转 | 双槽上下文 | notebook 工具 |
|---|---|---|---|
| 解决 | 视觉尾窗**有界** + 前缀不碎 | 头部**可增量写**的记忆区 | 跨会话**持久记忆** |
| 前置 | 链根独立 + Δ-rope | 链根独立 + insert-prefill + 快照回滚 | 无(纯 harness) |
| 共同基元 | **链根/位置基址**、块表重写、Transient 记账 | 同左 + GDN 语义 | — |

三者可以叠加:**notebook 提供稳定前缀 → 窗口旋转提供有界视觉尾窗 → 双槽(若上)提供会话中可写的冷区**。
本设计只交付中间那一层,不把 owl 绑到另外两层的产品决策上。
