# GGUF × KVMem · 论文量级 execution view（2026-10-23）

> 目标：按 KVMem 论文 24GB 消费档口径，把 GGUF 的 execution view 从 8K
> 提到论文量级（FP8 KV，设备池 ~96K，view 64K/80K）。

## 1. 档位

```text
profiles/qwen38_27b-3090-gguf-kvmem-64k.toml
  kv_fp8 = true
  workspace_per_req = 65536

profiles/qwen38_27b-3090-gguf-kvmem-80k.toml
  workspace_per_req = 81920   # 论文 Table 3 的 80K execution view
```

模型：`Qwen3.8-27B-Q4_K_M.gguf`，单 3090 Ti 24G，`query_replay=true`，
`snap_max=0`（replay 用专用 GDN 缓冲）。

## 2. boot 账

```text
per_tok=32768B (fp8) → pool cap=100864 tok / 3152 页
64K profile: workspace 2048 页 + chunk 16 = 2064 页 ✓
80K profile: workspace 2560 页 + chunk 16 = 2576 页 ✓
```

## 3. 实测

coherent needle，code 在 ~1/9 处，问题在末尾：

| ctx | workspace | 结果 |
|---:|---:|---|
| 60K | 64K | `BLUEBIRD-42` |
| 90K | **64K** | **`:`（仍丢针）** |
| 90K | **80K** | **`: BLUEBIRD-42`（命中）** |

90K/80K 档：

```text
final view=2560 页
target-hash block=312 hash=0395abd117f92331
[kvmem-replay] query replay:ctx=89978 base=89952 t=26
```

零 IMA/Xid；池 100864 > 90K 上下文，本档没有触发 host 下沉，
是纯 execution-view 质量对照。

## 4. 结论

1. **64K view 对 90K 上下文仍不够**；**80K 才命中**。这正是论文 24GB
   消费档的 80K execution view 口径。
2. 60K 上下文用 64K view 已命中；90K 需要 80K。
3. 当前 24GB + GGUF Q4_K_M + FP8 KV 可以做到 80K view（池 ~100K），
   与论文 Table 3 的 “KVM EM 80K / 1M virtual” 一致。
4. 但本档池 > 上下文，KVMem 的 host/NVMe 虚拟化未真正受压；下一步要在
   80K view 下把池压到 <90K，验证 host 下沉 + 80K view 的组合。

## 5. 复现

```bash
./target/release/server -p profiles/qwen38_27b-3090-gguf-kvmem-80k.toml \
  --set 'server.bind="127.0.0.1:8145"' --log-level info
```

`/tmp/needle_coherent10_64.py`：90K coherent filler + code@~6.6K + 末尾问题。

## 6. 80K view + 85K 池：完整虚拟化组合（2026-10-23）

把 `vram_reserve_mb` 提到 **1500**，设备池压到 **85568 tok / 2674 页**，
90K 上下文真正触发 host 下沉：

```text
pool 85568 tok < ctx ~90K
view 81920 tok = 2560 页
view+chunk = 2576 页 < pool 2674 页 ✓
```

90K coherent needle 实测：

```text
content: ": BLUEBIRD-42"
target-hash block=312 hash=0395abd117f92331
部分驻留:下沉 126/148/91/105/78/38 块；回灌 110/132/75/89/62/11 块
[kvmem-replay] query replay:ctx=89978 base=89952 t=26 view=2560 页
```

`/debug/vram`：host KvBlock **2.95 GiB**（2812 条），GPU 池仍装 85.5K。
零 IMA / Xid。

### 6.1 query replay 仍非因果（新负结果）

同 80K view / 85K 池，`query_replay=false` 复跑：

```text
content: ": BLUEBIRD-42"   # 与 on 逐字相同
```

⇒ 在 90K 这一档，**80K view 本身已让模型看见针块**；query replay 没有改变输出。
（query replay 仍是 step-level/多轮的基础件，但不要把它当 90K 的修复。）

### 6.2 结论

- 64K view 不够；**80K view 是这一档的门槛**，与论文 80K execution view 对齐；
- 80K view + 85K 池 + host 下沉 + 部分驻留可跑通 90K coherent needle；
- 24GB 3090 Ti + GGUF Q4_K_M + FP8 KV 上，论文的 80K execution view 组合
  已复现；
- 下一步若要 1M virtual workspace，瓶颈转到 host/NVMe 容量与 80K view 的
  step-level/compact 语义，而不是 execution view 预算。
