### 1.1 XQA 换 prefill?(用户令"换核")—— 立案即结案

| 步骤 | 结果 |
|---|---|

—— "哪个核快"是 **(核, 形状)** 的属性。

### 1.4 CUDA 图捕获语义:实测 → 挖隐患 → 上守卫

**实测**(`/tmp/captest/{captest,replay}.cu`,3090 Ti/sm_86/CUDA 13.2):

| 捕获窗内操作 | 捕获 | 节点 | 回放(3 次) |
|---|---|---|---|
| `cudaMemcpyAsync` H2D **pinned / pageable** | ✅ / ✅ | 1 / 1 | ✅ 值对 / ✅ 值对 |
| `cudaMemcpyAsync` D2H **pinned / pageable** | ✅ / ✅ | 1 / 1 | ✅ 值对 / ✅ 值对 |
| `cudaMemcpyAsync` D2D、`cudaMemsetAsync` | ✅ | 1 | — |
| **同步 `cudaMemcpy`** | ❌ `cudaErrorStreamCaptureImplicit` → EndCapture `…Invalidated`,nodes=0 | | |
| **`cudaMalloc`**(Global) | ❌ `cudaErrorStreamCaptureUnsupported` → 捕获作废 | | |
| **`cudaMalloc`**(Relaxed) | ⚠️ op+End 都 success,但 **nodes=0** ⇒ **静默没入图** | | |

⇒ **边界是「同步 vs 异步 / 可重放 vs 不可重放」,不是"H2D/D2H"**。
(此结论**更正**了本会话中我先前"pageable 源 async 拷贝不可捕获"的说法 —— 实测可捕获且回放正确;
工程上仍推荐 pinned,仅为省驱动 staging 税。)

**FI plan 的 H2D 隐患(挖出 + 已堵)**

```text
① 我们 Rust  server/flashinfer.rs:37/46/78   host_staging: Vec<u8>   ← **普通堆(可分页)**
                                       :153  传给 owl_fi_prefill_plan(page_locked=…)
② 我们 adapter cu/flashinfer/owl_fi_attention.cu:163  → PrefillPlan(..., page_locked, ...)
③ 算子内(上游头) include/flashinfer/attention/scheduler.cuh:504
      cudaMemcpyAsync(int_ws ← page_locked_int_buffer, H2D, stream)   ← **那一枪在这**
```

- **归属**:缓冲是我们的、调用链是我们的,**memcpy 由 vendored 算子头打出**;
  它不走 `Command` 通道 ⇒ **G2 捕获白名单看不到它**。
- **为何危险**:该 H2D 是 **async + pageable ⇒ 可被捕获**;而 `host_staging` **可变**
  (换形状重算 plan 会重写)⇒ 若 plan 在捕获窗内算,图里就烘进"从可变 host 缓冲现取内容"
  的 memcpy 节点 ⇒ 回放期把**别人的调度表**拷进 int_ws = **错表/越界,且不报错**。
- **旧 fork 同病史**(备份 `/tmp/fi-fork-old/include/.../scheduler.cuh:504` 同一行)⇒ 继承老账,非换源引入。
- **上游本意**:Python 侧该缓冲是 `pin_memory=True`(`flashinfer(外部存档)/flashinfer/attention/_core.py:87`)
  —— 我们传普通 Vec,**名实不符**。
- **已做**:`server/flashinfer.rs` 加硬门 —— **捕获期 plan 未命中 ⇒ 结构化拒**(上层 `Ok(None)` → eager 原路),
  并在注释里写明更强做法(每形状独立 staging ⇒ 节点源恒定)。
- **未做(待裁决)**:① `host_staging` 真上 pinned(修名实 + 省税,**不解决内容可变性**);
  ② 每形状 staging 缓冲(即使被捕获也语义正确);③ 把捕获语义探针收编成 kernels 单测。

## 2. 关键决策表

| 决策 | 理由 / 证据 |
|---|---|
| XQA **不做** prefill 主路径 | CUPTI 同请求 A/B:FI 快 **4.1×**(XQA 是 decode 形状核,q=T 仅 ~9 TFLOPS) |

| 生产档 `xqa_prefill = false` | 主路径净亏;留白名单 + 一行开关可复验 |
| 捕获期 plan 未命中即**拒** | 实测 async+pageable H2D 会被合法捕获 ⇒ 若不拒 = 静默烘错节点 |

## 7. 工具与环境口径(复用要点)

- **逐核设备时间**:`CUPTI in-engine`(`cargo build -p server --features perf,cupti` +
  `[probes] perf_level="gpu"`)—— 本机最可靠;**nsys 对 FI 档会丢 2/3 核**(不要单靠它)。
- **相位口径**:`engine.phase.prefill`(需 `--features perf`);单发噪声大,判收益要**多轮交替 boot**。
- **换核门四层**:单算子 host 参考 → 单算子同形状测速 → 引擎级**定量**(`prefill_cksum` 对独立核)
  → 引擎级**逐字**(greedy,注意"近并列翻面"≠缺陷);外加回归套件。
- **实验脚本**:`/tmp/owl-pf/{xqapf_ab.py,idchk2.py,idchk_fi.py,cksum_ab.py,gpuprof2.py}`;
  捕获语义探针 `/tmp/captest/`(**在 `/tmp`,下次要用先收编进树**)。
- ⚠️ **配置注入要幂等**:`kv_fp8 = true` 这类整行替换会在"配置已含该键"时造出**重复键**
  → server 静默 exit 1(本轮踩过)。
- ⚠️ **GPU 抢占**:并发会话会用 `nvidia-smi` 扫显存清理,**可能在跑测时被 SIGKILL**
  (本轮探针三次不同点被杀、零输出)——判据:换 GPU / 缩短子集重跑,别急着改代码。
- ⚠️ 杀进程一律 **PID 列表 + `/proc/pid/exe` 双验**,勿用 `pkill -f`(会匹配自身命令行)。
